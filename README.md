# Apex Entertainment Corp. — GitHub Pages Roleplay

## Publish or update it
1. Upload `index.html` to the root of your GitHub repository, replacing the older version when prompted.
2. Keep `README.md` in the root if you want the project instructions visible.
3. Open **Settings → Pages** and publish from `main` and `/(root)` if Pages is not already enabled.
4. Wait for the deployment to finish, then refresh the published site.

## Roleplay sign-in
- Developer username: `Apex Entertainment Consoles`
- Developer passcode: `ApexStatRoom`
- Any other username becomes a community account.

## Updated features
- More company-style dashboard and communications layout.
- Reply directly under community posts; replies are shown in conversation threads.
- Developer can reply as Apex or ask active moderators to reply to a post.
- Context-aware simulated replies in Live Inbox, Apex Gmail, and Conference.
- The fictional giveaway flow uses obviously made-up addresses with the placeholder region `ZZ`; it must not be used for real shipping.
- Existing console lab, 107-game portfolio, playtests, HR tools, applicant hiring, ban center, Horizon Plus, and FAQ remain included.
- A visible **THIS SITE IS FOR ROLEPLAY ONLY** notice remains on the site.

## Important limitations
This is a static browser-only simulation. It saves data to localStorage in the current browser; it does not synchronize between different users/devices. The contextual replies are rule-based roleplay responses, not a connected generative-AI service. A real AI backend or reliable speech-to-text would require an external service. Developer credentials are visible in client-side source code and are for roleplay only, not real security. No real email, orders, payments, shipping, hiring, or financial transactions occur.
